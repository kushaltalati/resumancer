# Writing rules for the tailored resume

Priority: **Accuracy > Relevance > Impact > ATS keywords > Brevity.**

- Every bullet traces to a profile entry. Quote numbers exactly; never round grades.
- Verbs: *Built / Designed / Shipped / Owned* only for solo work. *Built with one teammate*, *on a team that*, *led an N-person team; teammates built X* for shared work. Never let a teammate's result read as the user's; if the headline number is someone else's design, say whose and state the user's own measurable part first.
- One idea per bullet: what, how, measured result, in that order. Two rendered lines maximum (~200 characters); one line for achievement rows.
- Use the posting's own vocabulary where the profile supports it (if the posting says "operating systems" and the user has OS evidence, write "operating systems", not "OS fundamentals"). Never add a keyword without evidence.
- Section order follows the reader: students and career-changers lead with the entry that proves the posting's must-have (often projects); professionals lead with experience. Education goes first only when the school or the year of study is itself the screen.
- Dates on every entry, including projects. Grade with its scale (8.07/10, 3.8/4.0). Links to the user's own repos, not to an upstream or an instructor's repo.
- Labels the user has ruled out in profile §0 (for example "course project") are never used, but ownership markers inside bullets stay.
- Skills rows list only items demonstrated somewhere on the page or in the profile's attested pool. Remove a skill before the page lies about it.
- Cut order when over one page: volunteering → weakest project → third bullet of each entry → coursework line → profile summary.
- No photo, no tables for layout, no two-column body, no text in images: automated screens must read it top to bottom.
- Spelling convention from profile §0 (US/UK); consistent en-dashes for date ranges.
